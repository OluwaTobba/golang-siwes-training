## 📋 Overview

This repository contains the code produced during a 24-week SIWES industrial training attachment focused on the **Go programming language**. The training followed a structured weekly curriculum, progressing from language fundamentals through to a microservice with REST and gRPC interfaces, containerisation, and Kubernetes deployment.

Each week has its own folder (`week01/` -> `week24/`) containing working Go source files (and supporting config files) for that week's learning objectives. The code was run and checked on Windows with PowerShell, Docker Desktop and its built-in Kubernetes.

## 🚀 Capstone Project (Week 24)

An **Inventory Management Microservice** that brings together the skills from the programme.

### What it does
- ✅ **Clean architecture** — `domain` (rules), `service` (use cases), `repository` (data), and `transport` (REST + gRPC) layers, with dependencies pointing inwards
- ✅ **REST API** — `chi` router, request logging, panic recovery, request IDs
- ✅ **gRPC interface** — `CreateProduct` and `AdjustStock`, sharing the same service layer as REST
- ✅ **PostgreSQL** — GORM with `AutoMigrate`; the server retries until the database is ready
- ✅ **Business rules in one place** — stock can't go negative, SKUs are unique, inputs are validated
- ✅ **Health checks** — `/healthz` (liveness) and `/readyz` (readiness, pings the database)
- ✅ **Prometheus metrics** — `/metrics` via `promhttp`
- ✅ **Graceful shutdown** — REST and gRPC stop cleanly on `SIGINT`/`SIGTERM`
- ✅ **Docker** — multi-stage build into a small `scratch` image, run as non-root
- ✅ **Kubernetes** — Postgres, ConfigMap, Secret, and a 2-replica API Deployment with probes

> **Not included:** the capstone has no authentication on its endpoints. JWT is covered separately in Week 19. Postgres in the Kubernetes demo uses an `emptyDir` volume, so its data is lost if that pod is recreated; production would use a PersistentVolumeClaim or a managed database.

### Quick start (Docker Compose)

```powershell
git clone https://github.com/<your-username>/siwes-golang-training.git
cd siwes-golang-training/week24

# Build and start the API and PostgreSQL
docker compose up --build -d

# REST on http://localhost:8080   gRPC on localhost:50051
docker compose ps
```

Try it:

```powershell
$base = "http://localhost:8080"

# Create a product
Invoke-RestMethod -Method Post "$base/api/v1/products" -ContentType "application/json" `
  -Body '{"name":"Laptop","sku":"LAP-001","price":1500,"stock":10}'

# Reduce its stock by 3
Invoke-RestMethod -Method Patch "$base/api/v1/products/1/stock" -ContentType "application/json" -Body '{"delta":-3}'

# List products
Invoke-RestMethod "$base/api/v1/products"

# Test the gRPC interface
go run ./cmd/client
```

Stop it with `docker compose down -v`.

### Run on Kubernetes (Docker Desktop)

Enable Kubernetes in Docker Desktop (Settings → Kubernetes → Kubeadm), then:

```powershell
docker build --build-arg GO_VERSION=1.26 -t inventory-api:v1.0.0 .
kubectl apply -f k8s/inventory.yaml
kubectl rollout status deployment/inventory-api

# Reach the service from your machine
kubectl port-forward svc/inventory-svc 8080:8080
```

`GO_VERSION` must match the `go` line in `go.mod`.

### API endpoints

| Method | Endpoint | Description | Success |
|--------|----------|-------------|---------|
| `GET` | `/api/v1/products` | List all products | `200` |
| `POST` | `/api/v1/products` | Create a product | `201` |
| `GET` | `/api/v1/products/{id}` | Get a product by ID | `200` |
| `PATCH` | `/api/v1/products/{id}/stock` | Adjust stock (`{"delta": -3}`) | `200` |
| `DELETE` | `/api/v1/products/{id}` | Delete a product | `204` |
| `GET` | `/healthz` | Liveness probe | `200` |
| `GET` | `/readyz` | Readiness probe (checks the database) | `200` / `503` |
| `GET` | `/metrics` | Prometheus metrics | `200` |

### How errors are mapped

| Domain error | REST | gRPC |
|--------------|------|------|
| `ErrInvalidInput` (bad data, duplicate SKU) | `400` | `InvalidArgument` |
| `ErrProductNotFound` | `404` | `NotFound` |
| `ErrInsufficientStock` | `409` | `FailedPrecondition` |
| anything else | `500` | `Internal` |

## ▶️ Running Individual Weeks

Every week is run from inside its own folder. If a folder has no `go.mod`, create one first (this fixes the `go.mod file not found` error):

```powershell
go mod init github.com/<your-username>/siwes-golang-training/weekNN
go mod tidy        # downloads any dependencies
```

Then run it the way the week requires:

| Weeks | Command | Notes |
|-------|---------|-------|
| 1–10, 12 | `go run <file>.go` | Single-file programs, e.g. `go run control.go` |
| 11 | `go run .` | Multi-file package with `utils/` |
| 13 | `go run server.go` | Listens on `:8080` |
| 15 | `go run serial.go` | |
| 16 | `go run db.go` | Needs PostgreSQL (see below) |
| 17 | `go run gorm_demo.go` | Needs PostgreSQL and its own database |
| 18 | `go test -v ./...` | Tests are not run with `go run`. Also try `go test -cover ./...` and `go test -bench=. ./...` |
| 19 | `go run auth.go` | Needs `go mod tidy` for the JWT library |
| 20 | `docker compose up --build -d` | Docker Desktop must be running |
| 21 | `go run . ping go.dev -p 443` | A CLI: `go run . --help`, or `go build -o devtool.exe .` |
| 22 | `go run ./server` then, in a second window, `go run ./client` | Streaming and unary calls |
| 23 | `kubectl apply -f k8s/` | After `docker build -t go-api:v1.0.0 .` |
| 24 | `docker compose up --build -d` | See the capstone section |

### A PostgreSQL for Weeks 16, 17 and 24

The simplest option is Docker:

```powershell
docker run --name siwes-pg -e POSTGRES_PASSWORD=password -e POSTGRES_DB=siwes_db -p 5433:5432 -d postgres:16
```

Then set the port in the connection string to `5433`. Week 17 uses its own database (`siwes_gorm`) because it would otherwise clash with Week 16's `users` table.

## 🧰 Troubleshooting

| Problem | Cause and fix |
|---------|---------------|
| `go.mod file not found` | The folder is not a module. Run `go mod init <path>` then `go mod tidy`. |
| `function main is undeclared in the main package` | The file has no `func main()`, or you ran a library file. Run the whole package with `go run .`. |
| `cannot run *_test.go files` | Tests run with `go test`, not `go run`. |
| Docker build says `go.mod requires go >= 1.25` | The image's Go is older than your `go.mod`. Write a matching `go X.Y` line in `go.mod`, or use a newer `golang:` image tag. |
| `failed to connect to the docker API` | Docker Desktop is not running. Start it and wait for "Engine running". |
| `password authentication failed for user "postgres"` | A different PostgreSQL is already using port 5432, or you forgot its password. Use the Docker command above on port 5433. |
| `go mod edit -go=1.22` fails in PowerShell | PowerShell splits `-go=1.22` at the dot. Quote it: `go mod edit "-go=1.22"`. |
| `go.mod: existing contents have changed since last read` | A file-sync tool (such as OneDrive) touched the file mid-command. Re-run, or work outside a synced folder. |
| HPA shows `<unknown>/70%` | Docker Desktop has no metrics-server, so CPU can't be read. The manifest itself is correct. |
